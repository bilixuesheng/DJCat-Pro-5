# 反弹窗拦截：助手在重启时重写自身版本资源的产品名，可逆、更新后重套

教室里有「弹窗拦截 / 桌面管理 / 安全防护」类软件，会按窗口特征自动关闭它判定为"广告弹窗"的窗口。电教猫的投送、设置、各种对话框被这类软件误判——窗口刚出现几秒就被关掉（进程仍在后台），重装、换安装目录都无效。已在实机确认：这类软件按 exe 版本资源里的**产品名（ProductName）**匹配，把 `电教猫 Pro 5` 改成 `DJCat Pro` 后不再命中，窗口持续显示。

据此加一个默认关闭的开关「反弹窗拦截」。开启后把 `djcat.exe` 版本资源里的 `ProductName` 和 `FileDescription` 改成伪装产品名（默认 `DJCat Pro`），关闭则写回 `电教猫 Pro 5`。运行中的 exe 文件被锁、改不了，所以改动必须在电教猫退出之后由一个独立助手完成，再重启电教猫——这一步复用现有的 `updater.exe`（给它加一个"改版本资源"模式），而不是另写进程：它已经有等待主进程退出、必要时 UAC 提权、以及关键的**降权重启**（借 Explorer 令牌用 `CreateProcessAsUserW` 以普通用户身份拉起电教猫，否则配置会被写成管理员属主）。

几处和直觉不同、需要记下来的决定：

1. **用运行时 `UpdateResourceW` 正确重写资源，不手搜字节、不等长覆盖。** 参考做法是"在 exe 里按 UTF-16 找到产品名字符串、等长覆盖字节"，它要求新名和旧名字符数相同（`电教猫 Pro 5` 9 个字符 → `DJCat Pro` 9 个字符）。但「换一个伪装名称」会生成任意长度的随机名，等长覆盖做不到；而且手搜字节依赖资源布局、脆弱。`BeginUpdateResourceW`/`UpdateResourceW`/`EndUpdateResource` 重建整块 `RT_VERSION`，长度任意、结构正确。

2. **还原不留备份文件。** 原始产品名就是常量 `电教猫 Pro 5`（`APP_NAME`），关闭开关 = 把这个已知字符串写回去，不需要 `.bak`、不会留下副本或临时文件。

3. **每次 Client Update 后自动重套。** Client Update 是整目录替换，换上的新 `djcat.exe` 产品名又是 `电教猫 Pro 5`。所以开着开关时，更新流程在重启前顺带重套一次伪装名；启动时再核对一次 exe 当前产品名兜底（覆盖重装、手动替换等情况），不一致就重套。

4. **伪装名像正常软件名，不用随机十六进制。** 「换一个伪装名称」从内置英文词拼接再加一位 2–9 的数字（如 `DailyTeachTool 4`）。目的是躲开一个误杀，不是制造另一个：一串乱码产品名在文件属性里反而显眼、更招杀毒怀疑。

## Considered Options

**永远发布中性产品名（构建期一行改掉，无开关）**：最省事，`deploy.py` 把 `--product-name` 改成 `DJCat Pro` 即可，零运行时逻辑。但去掉了用户的可控开关，也让所有机器都对这类软件隐身——不是想要的默认；而且 IT 可能按产品名识别软件，默认换成英文反而不便。

**构建期生成一个只有版本资源不同的伪装副本，开关时做文件替换**：用户机上只做文件替换、不自改资源，最安全。但构建期烤死的是单一固定名，给不了「随机换名」；要支持随机换名就还得带上运行时改资源的逻辑，等于两套机制并存。

**运行时按字节搜索 + 等长覆盖**（参考方案）：不重建资源结构。但受等长限制、给不了任意长度的随机名，且依赖资源布局、脆弱。

**每次启动生成随机命名的副本当主进程运行（原安装不动）**：能做到"每次启动都换名"而无需重启。但一个从随机命名临时副本、每次还换名启动的进程，几乎必然被杀毒报毒——用一个更大的误杀换掉一个小误杀；还要重做单实例、`APP_DIR` 识别、Portable Mode 数据目录和 `updater.exe` 的重启路径（它们都假设主进程是 `APP_DIR` 里的 `djcat.exe`）。

**自动轮换产品名（移动靶）**：对会学习/更新黑名单的拦截软件更稳。但改磁盘上的 exe 必须在没运行时做，"每次启动换名"等于每次启动都退出重启，体验无法接受；折中成"手动换名、下次重启生效"已满足"可变"的诉求。（**此条后续已推翻**——实机确认拦截软件会把用过的伪装名重新拦下来，见文末 Update：改成"每 N 天而非每次启动、启动时完全静默换名"，原顾虑据此化解。）

## Consequences

- **电教猫会改写自己磁盘上的 `djcat.exe`。** 这类自改行为可能触发少数杀毒软件的启发式。本工程的 exe **没有代码签名**（`deploy.py`、CI 都不签名），所以不存在"改动破坏签名"的问题；但也意味着没有签名可供第三方据以信任。
- **只躲得开按产品名匹配的拦截软件。** 若某个拦截软件按窗口类名、进程名或窗口标题匹配，改产品名无效。窗口标题另有个性化设置可改，进程名/文件名不在本功能范围。
- **界面观感不变。** 电教猫没有任何地方读取自身版本资源（已核对）；单实例靠 `QSharedMemory("DJCatPro5")` 与 IPC 窗口类，与产品名无关；界面标题来自 `APP_NAME` / 个性化设置。改产品名只影响 Windows 文件属性和任务管理器显示。
- **开启、关闭、换名都要重启一次**（退出后才能改被锁的 exe），由助手等待退出、改资源、再降权重启。per-user 安装（可写、常见）全程无 UAC；装在 Program Files 才弹一次。
- **开着开关时，每次 Client Update 后会自动重套一次伪装名**（更新流程内重套 + 启动自检兜底），用户可能察觉更新后多一次短暂重启。
- **不触碰任何第三方软件**：本功能只改电教猫自身呈现给系统的名字，不注入、不挂钩、不修改/关闭/卸载任何别的程序。

## Update（2026-11）：增加「管理模式」，自动轮换从被否决转为默认

上面「Considered Options」里否决了「自动轮换产品名（移动靶）」，理由是"每次启动换名 = 每次启动重启，体验不可接受"。现已在实机确认：这类拦截软件会把用过的伪装名**重新拦下来**，一次性手动换名不足以长期规避。据此推翻那条否决，在总开关之下新增「管理模式」。

- **总开关下再分「自动管理 / 手动管理」**（首次开启默认自动）。手动管理即原有行为——手动随机换名，另新增填**自定义名**（最低校验：非空、去空格、不等于 `电教猫 Pro 5`；**不拦中文**，填含「电教猫」的名字仍会被按名命中，这是用户自担的选择）。
- **自动管理**按**轮换间隔**（默认 3 天，可填 1–30）自动随机换名。原否决的核心顾虑（"每次启动重启"）这样化解：不是每次启动换，而是每隔 N 天；且换名挂在**启动时**——每次启动检查距「上次换名日期」是否 ≥ N 天，到点才**完全静默**地走一次退出→随机换名→重启，复用现有 `_applyAntiPopupBlock`，不弹任何提示。选启动时而非退出时，是因为教室电脑常被硬断电、退出路径未必跑得到，而启动必然发生，最可靠。
- 到点判定与 `interval_tasks.py` 同形：从「上次换名日期」算起，错过多个周期只补换一次；该日期落在未来（主板电池没电、时钟被重置）时当作时钟出错，立即换名并重设基线；时间一律经 `clock.py`。任何一次换名（自动轮换、手动随机、手动自定义、首次落名）都把「上次换名日期」更新为当天。首次开启（默认自动）**立即随机**落一个名，不再停留在所有机器共享的 `DJCat Pro`。
- 切换管理模式、改轮换间隔都**不重启**（只改 `cfg`，下次换名才生效）；只有开关总开关和真正换名才重启。

新增配置（`Compatibility` 组）：`antiPopupBlockMode`（`auto`/`manual`，默认 `auto`）、`antiPopupBlockRotateDays`（默认 3，范围 1–30）、`antiPopupBlockRotatedOn`（ISO 日期，上次换名日期）。原有 `antiPopupBlockEnabled`、`disguisedProductName`、`antiPopupBlockTipDismissed` 保留。

本次新增的 consequences：

- 开着自动管理的机器，每隔 N 天的第一次启动会**多一次静默重启**（无提示，老师可能察觉软件自己闪了一下）。
- 自动生成的随机名**未经实测**，个别名可能恰好不管用或命中别的规则（与上文"伪装名像正常软件名、不用随机十六进制"同源的风险）。
- IT 若按产品名识别本软件，自动管理下名字会**周期性变化**；当前伪装名在设置页自动管理卡片上**只读可见**，供人工核对。
