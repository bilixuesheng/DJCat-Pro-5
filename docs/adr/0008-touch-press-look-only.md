# 触控只补按下的外观，输入仍交给 Windows

取代 ADR 0004。

Windows 要先分辨轻点、拖动和长按，才把触控转成鼠标消息，所以手指按住控件时没有按下态。ADR 0004 的办法是启动时传 `-platform windows:nomousefromtouch`，让 Qt 在落指瞬间自己合成左键按下。按下态是有了，但 Windows 自己的整套触控处理也被绕开了，真机上陆续冒出问题，每一个都得另行仿造：

- 长按不再弹右键菜单（Qt 丢弃由鼠标触发的 `WM_CONTEXTMENU`）。自己计时补上后，时机始终对不上系统：用户要的是长按到圆圈变成方框、松手才弹菜单，这个时长由 Windows 的"笔和触控"设置决定，程序拿不到。
- 落指的那一下左键会改动输入框的光标和选区，长按选中的文字之前，选区就先没了。
- 手指拖标题栏走不了系统移动循环，只能改由 Qt 自己 `move()` 窗口，丢了贴边吸附。
- 时间选择器弹出面板里的勾和叉按着亮、松手不点。offscreen 复现不出来，兜底补点击后在真机上依然不行。

现在撤掉启动参数，触控输入照旧由 Windows 判定、由 Windows 发出鼠标消息。`app/platform/touch_input.py` 只做一件事：手指落下时把指下的按钮或卡片画成按下的样子，直到 Windows 自己的按下到来，或者手指抬起、挪出轻点容差。它只改外观，`setDown()` 不发 `pressed`／`clicked`，不会凭空产生点击。

## Considered Options

**继续在 Qt 合成按下的基础上逐项仿造**：长按、选区、标题栏、弹出面板每一项都要单独补，补出来的仍和系统行为有差，真机验证一轮就要等用户去一次学校。

**逐个控件接管 `TouchBegin`**：横幅和主页编辑态一直是这样做的，但要逐个改控件。本方案是同一思路的全局版，由一个应用级过滤器统一找出指下的控件。

## Consequences

- 长按、选区、拖标题栏、弹出面板都回到 Windows 原本的行为，ADR 0004 为它们加的补丁全部删除。手指拖标题栏重新经过系统移动循环，Background Effect 靠 `WM_ENTERSIZEMOVE`／`WM_EXITSIZEMOVE` 就能覆盖。
- 按下态只给鼠标按下时也会被按下的控件：`QAbstractButton`（按 `setDown`）和带布尔 `isPressed` 属性的 QFluentWidgets 控件（如 `CardWidget`）。按钮自动连发会被 `setDown(True)` 触发，所以自动连发的按钮不画；输入框、滑块、数值框和列表本身接住按下，指下是它们时不往外找卡片，也不越过滚动区。
- 自己接触控的控件（`WA_AcceptTouchEvents`，滚动区视口除外）自管按下态，跳过；否则抬手时这里先把按钮复位，横幅就判断不出该不该点击。
- Windows 的按下一到，按下态就交给控件本身，抬手时不再复位。手指挪动后 Windows 当场补发按下，若此时再复位，随后的松开就点不中了。
- 轻点容差按微软触控规范的 2.7 mm（约 10 px）算，不用 Windows 上来自鼠标的 4 px `startDragDistance`。滚动区里的起滑取消沿用原有阈值，不受影响。
