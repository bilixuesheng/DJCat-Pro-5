# 进程守护挂在自动任务里，作为一种触发方式

教室里有些程序必须一直开着，学生关掉或程序崩溃后要有人把它拉起来。Process Guard 不是"到点执行一次"的规则，而是电教猫运行期间一直生效，但它仍然放进自动任务的同一个列表：「触发方式」在「固定时间」「软件行为」之外新增「进程守护」，和 Home Card Task 存在同一份配置里，共用 Task Master Switch 和每条的启用开关。有几处做法和直觉不同：

1. 它挂在"触发方式"下面，却没有触发时刻，也不参与定时匹配。老师想要的是"在自动任务里加一个功能"，挂在这里可以复用现有的列表外壳、新建对话框和展开编辑，不必在页面上再放一个列表。
2. 托盘菜单里没有「暂停守护」。要临时关掉被守护的程序，只能去自动任务里关掉这条规则或总开关：托盘图标学生也点得到，暂停入口等于把开关交给了守护要防的人。
3. 守护会放弃。电教猫拉起的程序连续 6 次撑不过 30 秒，或者根本启动不了（文件不存在、需要管理员权限），这一条在本次运行内停止守护，弹一次提示并在卡片上标出原因，直到重新打开开关或下次启动电教猫。需要管理员权限的程序不弹 UAC。

## Considered Options

**自动任务页里另开一个"进程守护"列表**：概念更干净，但页面上就有两个列表、两个总开关，而共用的 `ScheduledTaskPage` 外壳只有一个列表。

**单独做一个功能（新的 Default Home Card 加独立页面）**：和老师的说法"在自动任务里加"不一致，还要动固定的 Default Home Card 列表。

**按进程名认定**：任何同名的 exe 都算在运行，会被别处的同名程序骗过。按完整路径认定，和应用市场、Application Relocation 判断"程序在不在运行"用的是同一套规则。

**一直重试、不提示**：崩溃循环或误选了启动器 exe（它拉起主程序就退出）时会在后台无声地无限拉起，老师永远不知道守护早已失效。

**拉起时弹 UAC**：在讲台上 UAC 会一遍遍跳出来，学生点"否"照样失败。

## Consequences

- 守护规则和其他自动任务存在同一份配置里。日后要把它拆成独立的列表或页面，就得迁移已有配置。
- 开机静默启动后的前 60 秒只检查、不拉起，因为被守护的程序可能也在开机自启、比电教猫慢。平时每 3 秒检查一次，连续两次没看到才拉起，以放过程序自我重启时的空档。
- 收到 Windows 关机或注销通知时，以及电教猫自己的定时关机执行时，全部停止守护，否则先退出的程序会被拉回来、拖住关机。从托盘退出时，守护在点下「退出」的那一刻停止，"电教猫关闭时"的自动任务关掉程序不会被它拉回来。
- 应用市场的卸载、Application Update 和 Application Relocation 会先强制关闭程序再动文件，期间守护跳过受影响目录下的程序。迁移提交时，规则里的路径和其他配置一样，被改写到新位置。
