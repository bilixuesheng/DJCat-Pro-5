# Setting Preview 按真实尺寸复刻再缩小，不截取真实界面

Setting Preview 要"和真的很像"，最直接的做法是把真实界面 `grab()` 下来缩小。我们没有这样做：Setting Preview 用真实的逻辑尺寸（标题栏、导航栏、主页卡片、字号）和用户自己的数据（Home Card、导航项、托盘菜单项）重新排一遍，再整体等比缩小画进预览。主窗口类的预览按主窗口当前的宽高比排，随主窗口缩放实时变形。

## Considered Options

**截取真实界面再缩小**：画面最像，但有三个问题。一是会逼 Lazy Page 为了预览提前构造，违反懒加载规则。二是每改一次设置都要把整页重新截一遍，横幅亮度这类滑块拖动时会逐帧触发。三是设置页本身就在主窗口里，截主窗口会截到预览自己。

**保留示意风格**（灰条代替文字）：成本最低，但用户看不出改动在真实界面上的效果，这正是要解决的问题。投送、倒计时和时钟的背景预览例外：它们看的是背景和按钮位置，正文仍用灰条示意。

## Consequences

- 真实界面的尺寸改了，复刻要跟着改，测试应该钉住复刻的尺寸和真实界面一致。
- 复刻只画状态、不接受输入，所以不需要真实控件的交互逻辑。能直接复用的轻量组件仍然复用：主窗口复刻由真实的导航按钮、`BannerWidget`、主页 `ActionCard` 和标题栏按钮拼成，只是从不显示；托盘菜单由托盘自己的 `buildTrayMenu()` 建。横幅图片与主页共用同一份解码结果。只有挂在 `window()` 上的部件（标题栏本身、`NavigationBar`）不能借用，标题文字和底色照真实尺寸手画。
