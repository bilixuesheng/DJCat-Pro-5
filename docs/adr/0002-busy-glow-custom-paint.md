# Paint the Busy Glow instead of animating a QSS border

Busy Glow 原本由一个 60 ms 的 `QTimer` 驱动，每一帧用 `setStyleSheet()` 重写一条 `qlineargradient` 边框。这条实现同时踩了五个问题：`setStyleSheet()` 是 widget 级替换，忙碌期间 QFluentWidgets 给 TextEdit 装的整张样式表被顶掉，滚动条和选中色退回 Qt 原生外观；60 ms 只有 16.7 fps，且定时器不按真实经过时间补偿，主线程一忙就丢帧；每帧重解析样式表并 repolish；边框宽度从 1 px 变 2 px，开始和结束各挤动一次内容区；QSS 分四边绘制边框，粗渐变在圆角处留下斜向拼接。

改为在一个覆盖输入框的透明 overlay 上自绘：`QPainterPath` 圆角路径 + `QConicalGradient` 笔刷，多遍递减 alpha 描边伪造 bloom。

后来为了更接近 Siri／Apple 智能的边缘光，把光晕从"六遍宽笔叠加"换成了按距离计算的平滑光晕，见文末"平滑光晕"一节。

## Considered Options

- **继续用 QSS，只降低刷新频率**：改动最小，但解决不了圆角拼接、样式表被顶掉和 1 px 跳动，而且降频会让抖动更明显。
- **给输入框套 `QGraphicsBlurEffect` 做光晕**：能得到真模糊，但 graphics effect 会让整棵子树每帧重新栅格化，开销远高于多遍描边，且与下面阴影那条冲突。
- **在 overlay 上自绘多遍描边（已选择）**：一次描完整圆角路径，没有边的概念因而没有拼接；不触碰样式表因而不顶掉 Fluent 外观；不改变输入框几何因而没有跳动。

## Consequences

- **自限 60 Hz 是刻意的，不是疏忽。** 项目把全局 Animation Tick 调到 1 ms（见 `app/platform/animation_timer.py`），但 Busy Glow 每帧要做多遍抗锯齿描边，属于 CLAUDE.md 点名"必须自己限流"的那类回调。相位按真实经过时间计算，重绘按最小 16 ms 间隔合并。删掉这个限流会让 1 ms tick 把开销放大十几倍。
- **已长出的部分是一段连续圆弧，不是两条对称的臂。** 进场时光带从底边中点向两侧爬升，直觉上是两条臂，但两条臂会在起笔点和会合点重叠，alpha 叠加成两个亮疙瘩。表述成以底边中点为中心的单段圆弧后，底边接缝不存在；长满时换成闭合路径，顶边接缝也不存在。不要为了"两条臂"再去调笔帽。
- **锥形渐变按周长弧长参数化，不按原始角度。** `QConicalGradient` 按角度分配颜色，在扁矩形上会让颜色沿短边飞掠、沿长边爬行。色标位置按各边弧长占比重排后颜色才匀速绕圈。色标的角度位置和弧长位置随几何变化，在 `resizeEvent` 缓存；渐变对象本身每帧重建，因为它的颜色取决于相位。
- **深浅主题是两套配方，不是同一套调亮度。** 光感来自"比背景亮"，浅色主题下没有比接近白更亮的余地，因此浅色配方改为提饱和、降明度，靠"比背景浓"显形（具体倍数随配色换过一次，见"平滑光晕"一节）。这是观感上的妥协，不是参数微调。
- **`app/view/components/busy_glow.py` 依赖 `app/platform/dialog_animation.py`。** AI Markdown 对话框的卡片上挂着 `blurRadius=60` 的 `QGraphicsDropShadowEffect`，而带 graphics effect 的控件只要有子控件重绘就会整棵子树重新栅格化并重跑模糊。Busy Glow 把重绘频率从 16.7 Hz 提到 60 Hz，等于把这项开销放大 3.6 倍，因此光晕启动时复用 `dialog_animation` 的阴影 alpha 渐变把卡片阴影渐隐、结束时渐回。view 组件依赖 platform 适配层是这条约束的直接结果。内联整理所在的 `BroadcastEditPage` 是普通 QWidget，没有这个问题。
- Busy Glow 不表达完成度。转换耗时无法预估，任何百分比都是伪造的。

## 平滑光晕

六遍宽笔叠加的光晕在合成 alpha 上是阶梯：浅色主题下每一遍的边缘都清晰可数（实测亮度 255、253、249×5、240、239×3、230…），深色下也只是没那么显眼。要像 Siri 那样"一团光"，光晕必须是到边线距离的连续函数。

- **光晕是两个高斯之和，按圈画出来。** 近处的高斯（σ 5 px）撑亮度，远处的（σ 15 px）撑范围，再乘一个在 overlay 边界前收到 0 的窗口，否则最外圈会被 overlay 的矩形裁成直边。框内的距离按 1.6 倍计，光晕向框内渗得少，贴边的正文不被染色。实现上是一圈圈同心圆角矩形环，由外向内以 `Source` 模式覆盖、每圈向内多盖两圈：下一圈的抗锯齿外沿恰好在相邻两圈的值之间做线性插值，没有接缝。用 `SourceOver` 或 `Lighten` 画相邻圈都会在抗锯齿边上叠出一圈圈细纹；逐像素算距离则在 Python 里太慢，也不能为此引入 numpy（发版不打包它）。
- **光晕按低分辨率画，边线按设备像素描。** 光晕的标准差有 5–15 px，每 `HALO_PIXEL`（2）个逻辑像素一个缓冲像素就足够平滑，双线性放大后看不出区别；按设备像素画会让开销随 DPR² 增长。同一台机器上实测（每帧，毫秒）：100% 缩放旧实现稳态 7.8、新实现 5.9；150% 旧 12.9–14.5、按设备像素画的新光晕 16.6–20.3、低分辨率光晕 8.7–8.9；200% 旧 20.8–22.4、新 10.5–11.4。也就是说旧实现在 150% 以上就已经超出 60 Hz 的 16.7 ms 预算。边线仍用画笔描两遍，所以轮廓始终锐利。
- **入场窗口乘进渐变的 alpha。** 已长出的那段弧（仍是以底边中点为中心的单段弧）按弧长位置算出每个色标的可见度，直接乘进光晕和边线两张渐变的 alpha；不再把路径拆成主体加二十段渐隐短段逐段描，也不再整块填一遍 `DestinationIn` 遮罩。入场期间色标加密一倍，渐隐两端才不会被色标间距截成台阶。
- **颜色流动之外，光晕亮度也在流动。** 光晕渐变的 alpha 另乘一个沿周长起伏的亮度，由两组周期不同（2.9 s、4.7 s）、方向相反的波叠成，与颜色的流动（4 s）互不同步：光带看起来像液体在边上涌动，而不是一圈彩虹在匀速转。亮度下限 0.35，光带任何时候都是连续的一圈。呼吸幅度相应降到 ±12%，两种起伏叠在一起时不至于闪。
- **深色主题的光晕加性合成，边线正常叠加。** 光是"加"到背景上的：`Plus` 合成下越亮处越接近白热，才像自发光而不是一层半透明彩色贴纸；`SourceOver` 下粉彩色低 alpha 盖在灰底上只会发灰。边线若也加性合成，会在光晕最亮处饱和成纯白、失去颜色，所以边线仍按 `SourceOver` 画。浅色主题下加性合成会直接饱和成白，两者都正常叠加。
- **配色换成 Apple 智能的取色。** 蓝紫、紫、粉、珊瑚红、杏橙；仍不走满 360° 色相，避开感知亮度最高的纯绿纯黄。浅色配方改为提饱和 ×1.70、明度 ×0.95：粉彩色在白底上只能靠更浓的颜色显形，原来的 ×0.68 明度会让它发脏。
